01 · Verdict

结论摘要

复核后的整体体验健康度：可用但仍有风险。核心无账号搜索已恢复，剩余问题主要集中在等待反馈、诊断语义和故障恢复。

已经做对的事

  • 用户可以直接说书名、作者、语言和格式，不必理解来源站点。
  • 搜索与下载明确分开，避免“搜到即下载”的越权与误操作。
  • “找到、已尝试、已下载”被区分，成功状态可信。
  • 登录密码留在本机终端，文档持续提醒不要泄露凭据。
  • README 先讲用户目标，再放安装细节，信息顺序合理。

体验断层

  • 干净环境首次运行只有一句准备提示，等待期间没有阶段、进度或预计时长。
  • 首次准备与多镜像重试仍可能让用户等待较久，缺少阶段反馈和预计时长。
  • 失败建议暴露 {baseDir}、--json、代理环境变量等内部概念。
  • doctor 在所有来源不可用时仍返回顶层 ok: true，容易误导 Agent。
  • Z-Library 已补充标识符、出版社、版次和页数，但 Anna 候选仍缺少这些身份信息。

修复复核（2026-08-07）：隔离配置、无账号、未开启私网放行时，doctor 显示两来源均可搜索；联合搜索得到 6 条候选。Z-Library 前两个域名在实际搜索阶段失败后自动切到第三个域名，证明后备链不只停留在健康检查。

04 · Evidence

截图与实测证据

截图来自本次审计中实际打开并核验的 GitHub 页面；命令数据来自隔离的运行目录和配置目录，没有读取现有账号，也没有下载文件。

代码与文档交叉核验

  • RUNNER_COMMAND 在执行器中被固定为 python3 {baseDir}/scripts/run.py，因此占位符会进入真实错误建议。
  • 默认下载目录在实现中是 ~/Books，但 README 与 Skill 没有形成明确的默认行为约定。
  • INSTALL 要求迁移到 README 列出的 ZLIB_SKILL_*，README 实际没有列出这些变量。
  • 人类搜索表固定 110 列并截断标题/作者，不利于窄终端和辅助技术。

05 · Findings

问题清单与优先级

P0 表示本次环境中阻断核心任务；P1 表示显著影响成功率或信任；P2 表示结构性摩擦和可访问性风险。

P0 · 已修复

无账号后备路径在系统代理 / fake-IP 环境中可能完全失效

修复采用窄范围信任：Z-Library 支持匿名搜索并合并域名发现结果，Anna 轮换官方三个地址；只有可信 HTTPS 主机可接受 198.18.0.0/15 fake-IP，普通私网、字面 IP 和陌生重定向仍被阻止。

复核：doctor 双来源可用；联合搜索 6 条回归：可信 fake-IP、普通私网、陌生跳转分别覆盖状态：当前环境关闭
P1

首次准备过程缺少可感知反馈，连帮助页也要付出等待成本

干净运行目录下 --help 用时 9.34 秒。用户只看到一句 “Preparing the zlib-skill runtime...”，不知道是在建环境、装依赖、验证，还是已经卡住。真实网络较慢时，最长准备超时可到 300 秒。

影响：首用放弃、重复操作证据：Step 03建议：帮助绕过准备；真实任务显示阶段
P1

恢复建议违背“用户不需要懂命令”的产品承诺

错误与支持文档向用户暴露 {baseDir}、--json、ANNAS_BASE_URL、HTTPS_PROXY 等内部术语；搜索失败还默认建议登录 Z-Library，与“不会为了更多结果要求登录”的叙事形成冲突。

影响：恢复失败、信任下降证据：Step 07 / Support建议：结构化 next_actions，由 Agent 翻译
P1

诊断“执行成功”和“产品健康”没有分层

在两个来源都不可用时，doctor 仍返回顶层 ok: true。这对协议层或许表示命令完成，但 Agent 很容易把它解释为系统健康，或者需要遍历深层 sources 才能得出真实结论。

影响：错误总结、错误下一步证据：doctor 实测建议：增加 overall_status / usable
P1

候选版本的“身份信息”仍不对称，跨来源比较容易失真

Z-Library 结果已补充标识符（含 ISBN）、出版社、版次和页数，真实候选可以区分初版与第三版；Anna 的 HTML 结果仍只有基础字段。当前也没有统一的“字段缺失/可信度低”提示。

影响：Anna 候选仍可能选错版本证据：Step 05 / 真实候选建议：统一字段与元数据置信度
P2

文档交叉引用失效，用户在最需要帮助时找不到所指内容

SUPPORT 要求阅读 README 的“域名变化与网络边界”，但 README 没有该小节；INSTALL 要求迁移到 README 列出的 ZLIB_SKILL_*，README 也没有相应列表。文档分别都像是完整的，跨文档旅程却断开了。

影响：增加支持成本证据：README / INSTALL / SUPPORT建议：链接到具体锚点并做文档测试
P2

默认下载位置没有形成清楚、稳定的用户约定

实现默认写入 ~/Books，README 示例却总是显式指定 Downloads；Skill 的下载模板要求传入目录，但没有说明用户未指定时该问一次还是使用默认值。不同 Agent 可能给出不同体验。

影响：文件找不到、重复确认证据：Step 06 / code建议：明确默认并在成功前后复述
P2

双语与终端输出存在扫描和辅助技术负担

README、INSTALL、SUPPORT 采用中英逐段重复，屏幕阅读器会连续朗读两种语言，页面长度也接近翻倍。人类搜索表固定 110 列、标题和作者直接截断，没有换行或省略提示；窄终端和放大场景难以比较。

影响：阅读效率、低视力体验证据：文档截图 / print_search_table建议：语言分流；自适应行式结果

本次修复没有整体放宽 URL 检查。它只允许可信内置来源的 HTTPS 主机使用 198.18.0.0/15 代理 fake-IP；普通私网、localhost、字面非公网 IP 与未获信任的跳转继续拒绝。这一边界已由独立回归测试覆盖。

06 · Accessibility

可访问性风险

本节只能报告从页面结构、文案和终端格式中可见的风险，不能据此声称符合或不符合完整 WCAG。

可确认的优点

  • GitHub 渲染后的文档具有清楚的标题、列表和代码块结构。
  • 关键状态不只靠颜色表达，错误码和文字同时存在。
  • 错误对象包含 recoverable 与 suggestions，为辅助呈现保留了语义。
  • 密码不在聊天和日志中传递，减少辅助技术暴露敏感信息的风险。

需要验证与改进

  • 语言：中英逐段混排缺少页面级语言切换；读屏会反复切换语言模型。
  • 重排：固定 110 列终端表无法适应 200% 放大或窄宽度，长标题被静默截断。
  • 状态变化：运行环境准备没有阶段更新；在聊天界面中也应测试等待状态是否被读屏宣告。
  • 错误恢复：密集 JSON 与内部命令增加认知负担；应有一段自然语言摘要和一个明确下一动作。
  • 键盘/读屏：Agent 宿主的候选列表、编号选择和下载确认未在本次审计中测试。
07 · Roadmap

改进路线

先修核心可用性与错误语义，再提升选版质量，最后用真实用户研究校准。每一项都尽量给出可验证的完成标准。

NOW · 1 周

让用户能继续走

  1. 已完成：可信来源兼容 198.18.0.0/15 fake-IP，普通私网安全保护保持不变。
  2. -h/--help 和顶层无参数输出不触发运行环境准备。
  3. 替换所有面向用户的 {baseDir}；修复 SUPPORT 与 INSTALL 的失效引用。
  4. 搜索失败不默认建议登录，除非用户明确要求 Z-Library。
NEXT · 2–4 周

让 Agent 能正确解释

  1. doctor 增加 overall_status、usable_source_count 与结构化 next_actions。
  2. 首次准备显示“创建环境 / 安装依赖 / 验证完成”，并在聊天中合并为简短进度。
  3. 候选结果增加 ISBN、出版社、版次、译者或元数据缺失标记；提供详情展开。
  4. 明确未指定输出目录时的产品约定，并在下载前后复述。
LATER · 1–2 月

让体验可持续优化

  1. 拆分中英文档，以页面顶部互链代替逐段重复。
  2. 将人类搜索输出改为编号、换行、全标题的自适应格式。
  3. 在 macOS 系统代理、Clash fake-IP、Windows、Linux ARM 上做干净环境旅程测试。
  4. 引入匿名、可选的失败类别统计，验证最常见的阻塞点。
改进主题建议验收标准
首次准备干净环境执行 --help 在 500ms 内返回；真实任务每 10 秒内至少出现一次可理解的状态更新。
核心搜索当前环境已达成成功路径：无账号双来源搜索成功，且 Z-Library 在搜索阶段自动切换失效域名；仍需补充所有地址失败时的专门错误语义。
诊断语义两个来源都不可用时，overall_status = "unusable"；Agent 不需要推断深层字段即可准确总结。
恢复建议所有用户可见输出不再包含 {baseDir}；自然语言用户无需复制 JSON 命令完成标准恢复。
候选选择同名多版本测试集中，用户能在不打开来源站点的情况下正确选择目标版本；缺失元数据被显式标注。
文档自动检查本地链接和锚点；README、INSTALL、SUPPORT 之间没有失效引用。
08 · Research plan

下一轮体验研究建议

当前审计能找到结构问题，但无法代替真实用户。建议用 5–7 名目标用户做短程任务测试，覆盖熟悉命令行与完全不熟悉的两组。

建议任务

  1. 第一次看到仓库，判断是否值得安装，并完成安装请求。
  2. 无 Z-Library 账号，寻找一本公版书的英文 EPUB。
  3. 只记得部分书名，辨认正确作品。
  4. 面对三个相似版本，选择指定版次或译本。
  5. 人为制造来源不可用，观察能否独立恢复或正确求助。
  6. 下载成功后，找到本地文件并解释为什么相信它是正确版本。

核心衡量指标

首次有效候选时间
无账号任务成功率
错误版次选择率
无需人工支持的恢复率
对下载结果的信心
敏感信息误发率
09 · Limits

证据边界

以下内容没有在本次审计中直接验证，报告已将相关阶段标为“未验证”或“风险”。

  • 没有使用真实 Z-Library 账号，没有验证登录、token 续期和账号限制。
  • 修复后已获得两个来源的真实候选列表，但没有进入下载流程。
  • 为了避免产生文件与版权风险，没有执行任何电子书下载。
  • 本机界面捕获能力不可用，命令行证据以本次真实输出和耗时记录呈现，不以终端截图冒充。
  • 没有在实际 Agent 宿主中测试候选列表的视觉、键盘、读屏和跨轮次编号映射。
  • 没有进行真实用户访谈、可用性测试或统计分析；优先级基于核心任务影响和本次环境证据。
  • 已在隔离虚拟环境运行相关测试；下载、真实账号登录和不同操作系统仍需额外验证。
